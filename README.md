> **Статус: каркас.** Бизнес-логика ещё не реализована. Разделы с пометкой

## 1. Назначение решения

Чат-бот с подключённым мини-приложением в MAX для подготовки и согласования
документов внутри компании.

Автор загружает документ, ИИ извлекает из него поля и сверяет их с чек-листом
требований, показывая замечания со ссылкой на конкретное правило. Документ идёт
по маршруту согласующих с уведомлениями в боте. Решение «одобрить / вернуть /
отклонить» всегда принимает человек — модель не решает ничего.

## 2. Основной пользовательский сценарий

`[ЗАПОЛНИТЬ — пошагово, от подключения компании до статуса «Согласован»]`

Кратко:

0. Подключение компании: администратор создаёт компанию и делится приглашением,
   сотрудник подаёт заявку, администратор принимает её и назначает роли.
1. Вход в мини-приложение из бота. Личность — из подписанных данных MAX,
   роли — назначенные администратором; сам пользователь ничего не выбирает.
2. Мини-апп → форма загрузки документа.
3. ИИ-проверка → замечания со ссылкой на правило, либо «всё чисто».
4. Предпросмотр маршрута → отправка на согласование.
5. Согласующие получают уведомления в боте и принимают решения в мини-аппе.
6. После последнего одобрения — статус «Согласован» и уведомление автору.

## 3. Состав и архитектура решения

| Компонент | Технология | Назначение |
|---|---|---|
| `backend` | Java 21, Spring Boot 3.5.16 | REST для мини-аппа, стейт-машина согласования, интеграция с Bot API, ИИ-пайплайн |
| `frontend` | React 19, Vite, `@maxhub/max-ui` | Мини-приложение MAX |
| `postgres` | PostgreSQL 16 | Метаданные: пользователи, документы, маршруты, этапы |
| `minio` | MinIO (S3-совместимое) | Файлы документов. В БД только `storage_key` |
| GigaChat | внешний HTTPS-сервис | Только извлечение полей из текста. Нарушено ли правило, решает код |

Схема БД и границы модулей — в [CLAUDE.md](CLAUDE.md).

## 4. Запуск: одна команда

```bash
cp .env.example .env && docker compose up --build
```

Перед запуском заполните `.env` (см. раздел 6). После старта:

- Мини-приложение — http://localhost:8081
- API бэкенда — http://localhost:8080
- Консоль MinIO — http://localhost:9001

Проверено: полная пересборка без кэша — **235 с** при лимите кейса 300 с
(без учёта первоначальной загрузки базовых образов). Все сервисы поднимаются
в состояние `healthy`, бакет MinIO создаётся автоматически.

> Контейнеры — для воспроизводимой проверки. Рабочая версия продукта живёт
> в MAX: ссылка на бота и мини-приложение — на первом слайде презентации.

## 5. Необходимые параметры окружения

| Параметр | Обязателен | Назначение |
|---|---|---|
| `DB_PASSWORD` | да | Пароль Postgres. Без него compose не стартует |
| `MINIO_ACCESS_KEY` | да | Ключ доступа MinIO (≥ 3 символов) |
| `MINIO_SECRET_KEY` | да | Секрет MinIO (≥ 8 символов) |
| `MAX_BOT_TOKEN` | да | Токен чат-бота, выдаётся организаторами |
| `MAX_MINI_APP_URL` | да | Публичный HTTPS-адрес мини-аппа |
| `GIGACHAT_CREDENTIALS` | нет | Authorization key GigaChat. Без него ИИ-сверка деградирует (раздел 12) |
| `GIGACHAT_CLIENT_ID` | нет | Идентификатор проекта GigaChat; секрет уже входит в Authorization key |
| `GIGACHAT_MODEL` | нет | Модель извлечения полей; по умолчанию `GigaChat-2-Max` |
| `DEMO_MODE` | нет | `true` включает переключатель участника для проверки (раздел 10) |

## 10. Порядок работы с тестовыми данными

`[ЗАПОЛНИТЬ — состав сид-данных: организация, пользователи, роли, тип документа,
маршрут, набор правил]`

**Переключатель участника (`DEMO_MODE=true`).** Основной сценарий требует
нескольких людей с разными ролями: автор, затем согласующие. Чтобы один
проверяющий мог пройти цепочку целиком, в мини-аппе предусмотрен явный
переключатель «действовать как…» между предзаготовленными демо-участниками.

Это **механизм проверки, а не часть продукта**: он включается переменной
окружения и в рабочем режиме выключен. Реальный путь — идентификация
пользователя средствами MAX.

## 11. Описание работы с данными

- **Файлы документов** — в MinIO. В Postgres хранится только `storage_key`,
  бинарники в БД не попадают.
- **Метаданные и результаты ИИ** — в Postgres.
- **Доступ** фильтруется по роли и организации **до** обращения к LLM и **до**
  отдачи данных в интерфейс.
- **Маскирование ПДн.** Структурные идентификаторы (ИНН, СНИЛС, паспорт,
  телефон) заменяются плейсхолдерами регулярными выражениями **перед**
  отправкой в облачную модель. Реальные значения подставляются обратно
  локально при показе пользователю.
- **Флаг «содержит чувствительные данные».** Если автор его выставил, сырой
  файл не уходит в модель вообще: автор заполняет поля формой вручную, и
  проверка идёт по введённым значениям.
- **Привязка к источнику.** Каждое замечание ИИ ссылается на конкретное
  правило (`rule_id`), а не является свободным текстом модели.

**Модельные данные.** Чек-лист требований — это заранее подготовленный набор
правил в базе, а не живой запрос в государственную информационную систему.
Интеграция с ГИС в решении **не имитируется**: её нет, и это зафиксировано
здесь и в презентации.

## 12. Поведение без GigaChat

Недоступность внешней модели не ломает сценарий:

1. **Ключ есть, сервис отвечает** — полный разбор документа моделью.
2. **Ключа нет, таймаут или ошибка** — документ всё равно принимается и уходит
   по маршруту. Детерминированные проверки (наличие обязательных полей, формат
   значений) выполняются локально и продолжают давать замечания. Интерфейс
   честно сообщает, что разбор моделью недоступен, и не выдаёт отсутствие
   замечаний за успешную проверку.
3. **`AI_ENABLED=false`** — обращения к LLM отключены полностью.

## 15. Остановка и повторный запуск

```bash
# Остановить, сохранив данные
docker compose down

# Запустить снова
docker compose up

# Полный сброс, включая БД и файлы
docker compose down -v && docker compose up --build
```

Ошибка в одном сценарии не требует перезапуска решения: состояние документа
хранится в БД, пользователь продолжает работу с того же места.

**Выкладка на стенд** (для команды; каталог проекта на сервере):

```bash
./deploy.sh              # выложить свежий main
./deploy.sh <коммит>     # откатиться на прошлую версию
```

Скрипт обновляет код, пересобирает образы, ждёт `UP` от `/actuator/health` и
показывает, какой коммит выложен. Если бэкенд не поднялся, он сам подсказывает
команду логов и откат. Выкладка — ручная: выкладывает тот, кто готов сразу
проверить результат в MAX.

## 16. Известные ограничения

Сознательные границы MVP:

- Статус «Согласован» — внутреннее решение компании, а не юридически значимая подпись.
- Пользователь состоит в одной компании; набор ролей и маршрутов создаётся по
  умолчанию и через интерфейс не редактируется.
- Редактора файлов в приложении нет. Поле, найденное ИИ в DOCX, можно исправить прямо в файле:
  прежнее значение заменяется в тексте с сохранением оформления, получается новая версия. PDF так
  не правится — исправленный файл загружается новой версией.
- Работа ведётся только на синтетических тестовых документах; соответствие 152-ФЗ
  не заявляется.
- Согласующие на этапе — только заранее заданные ролью; произвольная
  отправка кому угодно не предусмотрена по продуктовым соображениям.
- Возврат документа на доработку перезапускает цепочку с первого этапа:
  документ изменился, значит прежние одобрения относятся к другой версии.
- Кворум «M из N» на параллельном этапе не реализован — требуется одобрение
  всех участников этапа.
- Межорганизационное согласование не реализовано.
- Сканы и фотографии без текстового слоя не распознаются: изображение нельзя замаскировать
  перед отправкой в модель. Приложение сообщает, что текста в файле нет, поля вводятся вручную.
- Семантическая детекция произвольного чувствительного контента отсутствует:
  только регулярные выражения по структурным идентификаторам, словарь
  ключевых слов и ручной флаг автора.
- Живой интеграции с государственными реестрами нет.
- Аналитика — три показателя на списке документов (число отправленных, медианный срок согласования,
  доля возвратов); отдельного дашборда нет.
- Статус документа по названию в боте доступен только участникам реальной компании: у бота нет
  переключателя «действовать как», поэтому документы демо-песочницы он не ищет и отвечает
  предложением открыть мини-приложение.
